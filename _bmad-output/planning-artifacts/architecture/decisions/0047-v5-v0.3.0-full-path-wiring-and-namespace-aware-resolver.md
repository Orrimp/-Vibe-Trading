# ADR-0047 — v5 v0.3.0 full-path wiring + namespace-aware Rust resolver

> ADR-0045 locked the canonical `LatencySlippageSimConfig { 30, 80, 8 }`
> and the two-namespace co-existence rule. v0.2.0 wired it through ONE
> of seven strategy paths (`momentum::run`). This ADR (a) confirms the
> K2 reachability verdict for the Group A data-source decision, (b)
> locks the per-path plumbing contract for the remaining 6 paths, and
> (c) lifts the namespace-aware report-resolver pattern from Bash
> (`scripts/verify_anchors.sh`) into Rust so the t1937 test stops
> aliasing canonical reports under noop SHAs.

## Context

The v0.2.0 ship (commits `d2cc343`, `c223d11`, `4dfa2d8`, `d191227`)
re-emitted 34 canonical anchors but the Sharpe-delta table audit
(`evidence/v5-latency-slippage-sim-v0.2.0-anchor-migration/reports/sharpe-delta-table-2026-05-27.md`)
revealed two operational gaps:

1. **6 of 7 strategy paths carry canonical SHAs that are byte-identical
   to their noop-baseline counterparts**, because `LatencySlippageSimConfig`
   is wired into exactly one `ScenarioInput` struct (`MomentumScenarioInput`)
   and the other 5 input structs (`SmaScenarioInput`, `PairsScenarioInput`,
   `TcnScenarioInput`, and the 5 modules `TcnScenarioInput` fans out to)
   default the simulator to noop. The simulator engine fires only in
   `momentum::run`'s buy/sell branches (lines 386-391, 434-439, 555-567).

2. **Group A data-source drift** — the 5 SMA/Composed scenarios picked up
   real Binance Parquet at re-emission time because of an unguarded
   runtime auto-detect in `crates/backtest/src/main.rs:977-1020`:

   ```rust
   let has_parquet = parquet_dir.exists() && <dir non-empty>;
   if has_parquet { load Parquet } else { synthetic }
   ```

   v0.2.0's Group A canonical SHAs are therefore "real-data oracle"
   SHAs even though the v5 sim itself never fired on those paths. The
   operator's Q1 must decide whether to revert (route a) or accept
   (route b) this drift. Architect M-T1 had to confirm route (a) is
   technically reachable before the operator could decide — that's
   the K2 falsifier.

3. **The `t1937_nine_strategy_anchors_unchanged` test** at
   `crates/reports/tests/strategy_anchors_unchanged.rs:94-99` resolves
   reports by lexicographic-sort-and-take-last, with no concept of
   the `version`/namespace column added in ADR-0045 D2. Wave A's
   2026-05-27 canonical reports sort after the original noop reports,
   so the test now compares the noop-locked constants against canonical
   bodies and fails. v0.2.0 whitelisted this; v0.3.0 fixes it.

## Decision

### D1 — K2 reachability verdict: **K2-REACHABLE-CHEAP** (~5 LoC in `main.rs`)

The synthetic-vs-Parquet branch is a single `if has_parquet` block at
`crates/backtest/src/main.rs:982`. The data source for Group A
(SMA/Composed) scenarios is NOT statically declared on the `Scenario`
struct — Group A scenarios all default to `ScenarioDataSource::Synthetic`
(lines 225-461 of main.rs) and never enter the realdata arms at lines
807, 902. The Parquet load is reached purely because the `else` branch
of the multi-symbol dispatch (line 972) walks the disk.

**Route (a) is reachable with a single CLI flag** added to `Args`:

```rust
/// Force synthetic-bar generation even when Parquet data exists on
/// disk. Affects only the single-symbol (SMA/Composed) dispatch arm
/// at main.rs:972 — multi-symbol scenarios (momentum / pairs / tcn /
/// patchtst / garch) are unaffected since they branch on the
/// statically-declared `ScenarioDataSource` enum.
#[arg(long, default_value_t = false)]
force_synthetic_bars: bool,
```

Then the auto-detect becomes:

```rust
let has_parquet = !args.force_synthetic_bars
    && parquet_dir.exists()
    && <dir non-empty>;
```

**Scope of impact**: ~5 LoC. Affects ONLY the `else` arm at main.rs:972
(single-symbol Group A). Does NOT alter the `ScenarioDataSource::RealData`
explicit-realdata path (which is correct as-is — those scenarios are
explicitly real-data by name and must stay real). No new feature flag
is needed; this is a runtime override.

**Alternative considered**: env var `BACKTEST_FORCE_SYNTHETIC=1`.
Rejected because CLI flags are introspectable via `--help` and
auditable in run logs; env vars are silent.

**K2 verdict therefore = REACHABLE-CHEAP.** Route (a) and route (b)
are BOTH live for operator Q1. The operator is no longer constrained
to route (b); their judgment governs.

### D2 — Per-path plumbing contract (closes ADR-0045 D2 gap)

The wiring contract for each of the 6 unwired paths mirrors the
`momentum::run` pattern at lines 386-391 / 434-439 / 555-567. The
field is added to the `ScenarioInput` struct, threaded through `run`,
and applied at the fill-accounting boundary via the
`sim_slippage_cost(qty, fill_price, side, cfg)` helper.

**Helper shared-location decision**: `sim_slippage_cost` currently
lives as a private function inside `crates/backtest/src/scenarios/momentum.rs:551`.
To avoid 7 copies, this ADR mandates **lifting the helper to a new
public module `crates/backtest/src/scenarios/sim.rs`** with the same
signature. The momentum module then `use`s it; the 6 new wiring sites
also `use` it. This is a behaviour-preserving move (the function body
is byte-identical) so anchor-additive per ADR-0038 § D6.a.

**Per-path audit table** (R1 of the v0.3.0 feature brief):

| # | Strategy | ScenarioInput struct | `run()` site | Wiring cost (LoC) | Cross-path |
|---|----------|---------------------|-------------|-------------------|------------|
| 1 | SmaComposed (5 scenarios) | `SmaScenarioInput` (cli_types.rs:124) | `sma_composed_run::run` at `scenarios/sma_composed_run.rs:298` | ~8 (struct field + match-config + 2 fill loops at lines ~505-540) | Independent |
| 2 | Pairs (2 scenarios) | `PairsScenarioInput` (cli_types.rs:178) | `pairs::run` at `scenarios/pairs.rs:67` | ~10 (struct field + fill-loop wiring; pairs has 4-symbol universe so the fill loop is more complex) | Independent |
| 3 | TcnOverlay (4 scenarios) | `TcnScenarioInput` (cli_types.rs:195) | `tcn_overlay::run` at `scenarios/tcn_overlay.rs:69` | ~8 | Shares struct with #4-#7 |
| 4 | TcnOverlayWeights (4 scenarios) | `TcnScenarioInput` (shared) | `tcn_overlay_weights::run` at `scenarios/tcn_overlay_weights.rs:31` | ~8 | Shares struct with #3 |
| 5 | PatchTstOverlay (1 scenario) | `TcnScenarioInput` (shared) | `patchtst_overlay_weights::run` at `scenarios/patchtst_overlay_weights.rs:46` | ~8 | Shares struct with #3-#4 |
| 6 | VolTarget / GarchVolOverlay (1 scenario) | `TcnScenarioInput` (shared) | `garch_vol_target_overlay::run` at `scenarios/garch_vol_target_overlay.rs:105` | ~8 | Shares struct with #3-#5 |
| 7 | ThresholdSweep (analysis paths) | `TcnScenarioInput` (shared) | `threshold_sweep::run_cell` at `scenarios/threshold_sweep.rs:56` | DEFERRED — analysis paths have no equity surface; sim has no meaningful effect | Shares struct |

**Total estimated LoC**: ~42 production + ~30 plumbing tests + ~5 CLI
override flag = **~77 LoC**. Aligns with v0.2.0's M-DEV Wave A cost
estimate of ~1 day.

**Cross-path consolidation**: Because TcnOverlay / TcnOverlayWeights /
PatchTstOverlay / GarchVolOverlay all share the `TcnScenarioInput`
struct, adding the field once auto-propagates. The 4 `run()` functions
each still need their own fill-loop wiring (one site per `engine.step`
call).

**ThresholdSweep is explicitly deferred**: It is a 2D analysis sweep
that emits a CSV (no equity surface), so applying `sim_slippage_cost`
is structurally noop for the report body. Confirmed at architect M-T1
as out of scope. Documented here to close the K6 ambiguity in the
v0.3.0 brief.

**GarchVolOverlay clarification**: The brief listed "GarchVolOverlay
(analysis paths)" as Group G with a verdict at M-T1. The
`garch_vol_target_overlay::run` path IS a strategy run (it has a fill
loop and an equity surface) — distinct from "analysis paths". This
ADR confirms `garch_vol_target_overlay` is **in scope** for R1 plumbing.
The "analysis paths" in Group G of the v0.2.0 Sharpe-delta table refer
to scenarios like `forecast-distribution-*` and `threshold-sweep-*`
which DO NOT have an equity surface — those stay out of scope.

### D3 — Namespace-aware Rust resolver (closes Q4; mirrors verify_anchors.sh)

The t1937 test's `find_backtest_report(scenario)` helper learns to
filter candidate reports by namespace (`noop-baseline` vs canonical).
Mirrors the Bash logic in `scripts/verify_anchors.sh:63-110`.

**Where the namespace lives**: the YAML front-matter of each report
file carries a `version:` field. Reports re-emitted under the v5
v0.2.0 canonical config sit in
`evidence/v5-latency-slippage-sim-v0.2.0-anchor-migration/reports/`
(and after v0.3.0 ship, in
`evidence/v5-latency-slippage-sim-v0.3.0-full-path-wiring/reports/`);
noop-baseline reports sit in every OTHER feature folder.

**Resolution algorithm** (Rust):

```text
fn find_backtest_report(scenario: &str, namespace: Namespace) -> Option<PathBuf>:
  match namespace:
    Noop:
      collect candidates under docs/archive/pre-bmad-spec/**/reports/backtest-*-<scenario>.md
        EXCLUDING any path containing
        "v5-latency-slippage-sim-v0.2.0-anchor-migration"
        OR "v5-latency-slippage-sim-v0.3.0-full-path-wiring"
      return lex-newest
    Canonical:
      collect candidates IN evidence/v5-latency-slippage-sim-v0.3.0-full-path-wiring/reports/
        AND evidence/v5-latency-slippage-sim-v0.2.0-anchor-migration/reports/
      return lex-newest
```

**Implementation hint for the developer**: keep the resolver in
`crates/reports/tests/strategy_anchors_unchanged.rs` (test-local) for
now. If a second test needs it later, lift to a `pub(crate)` helper in
`crates/reports/src/anchor_resolve.rs`. Do NOT prematurely lift to a
shared crate — YAGNI applies until a second consumer exists.

**Constant table extension**: the existing `STRATEGY_ANCHORS` table
at lines 41-77 STAYS pinned to noop-baseline SHAs forever. A NEW
table `CANONICAL_STRATEGY_ANCHORS` is added with the post-R1+R2
SHAs (populated by the developer at Wave C close). The test fans
out to both:

```rust
for (scenario, expected) in STRATEGY_ANCHORS {
    let report = find_backtest_report(scenario, Namespace::Noop);
    assert_sha(report, expected);
}
for (scenario, expected) in CANONICAL_STRATEGY_ANCHORS {
    let report = find_backtest_report(scenario, Namespace::Canonical);
    assert_sha(report, expected);
}
```

**Migration freeze**: ADR-0038 § D6 (anchor-additive contract) applies
to this table as it does to `evidence/anchors.toml`. After v0.3.0 ship the
canonical table is frozen unless a future ADR explicitly re-emits.

### D4 — Group A re-emission contract (depends on Q1 route)

This decision is gated on Q1 (operator-decide). The architect locks
the contract conditionally:

**If Q1 = route (a) "revert to synthetic baseline"** — recommended now
that K2 is REACHABLE-CHEAP:

- Wave B re-emission of the 5 Group A scenarios uses
  `--force-synthetic-bars` (the new flag from D1).
- The Sharpe-delta table for Group A reports CLEAN friction effect
  (synthetic + noop vs synthetic + canonical).
- The 5 noop-baseline SHAs for SMA/Composed stay valid as friction-free
  oracles (R-NR.1 preserved).
- Cost: ~5 LoC CLI flag + ~32 lines of Wave B run-script context.

**If Q1 = route (b) "accept real-Binance baseline as new oracle epoch"**:

- Wave B re-emission of the 5 Group A scenarios runs WITHOUT
  `--force-synthetic-bars` (default behaviour).
- The Sharpe-delta table reports "real-Binance vs real-Binance +
  canonical" — friction effect is mixed with the +$48k-+$83k data-source
  drift documented at v0.2.0 ship.
- The 5 noop-baseline SHAs for SMA/Composed become historical-only
  (no longer valid friction-free oracles); R-NR.1 needs amendment.
- ADR-0045 D2 is amended to drop the 5 SMA/Composed entries from the
  noop-baseline namespace; the canonical row count becomes the only
  reference for Group A.

**Architect lean** (recorded for transparency, NOT a decision): now
that K2 is REACHABLE-CHEAP, the cost asymmetry between routes (a)
and (b) has flipped. Route (a) was historically harder to argue when
"force synthetic" required a refactor; with a 5-LoC flag, route (a)
becomes the natural default — it preserves the friction-free oracle
for 5/68 anchors at trivial cost. The operator may still override
to (b) for forward-looking-realism reasons; that's their judgment
call. The Q1 reframe in feature.md surfaces this updated cost picture.

### D5 — Anchor namespace strategy (closes Q3; defaults to Q3 = (a))

Per analyst-recommended default Q3 = (a), the existing
`v5-realdata-medium-2026-05` namespace pin is extended (not
superseded) — the 32 currently-byte-identical-to-noop canonical SHAs
get **bumped** to the new R1+R2 outputs, same pin, new SHAs. Anchor
row count stays at 68 (or 63 if Q1 = route (b) retires the 5 Group A
noop rows).

ADR-0045 D2 is amended (not superseded) with a Changelog entry at
ship time.

If the operator explicitly picks Q3 = (b) "new pin
`v5-realdata-medium-2026-05-full`", D5 is overridden and a new ADR
amendment authored at M-T1 close. The standing default is (a).

### D6 — Cross-feature e2e re-check inventory (closes Q5; defaults to Q5 = (a))

Per analyst-recommended default Q5 = (a), all overlay/sizing-modifier
e2e divergence tests re-run under canonical config. The inventory is
**confirmed unchanged at 3 files** (plus 1 meta-gate):

| File | Purpose |
|------|---------|
| `crates/strategy/tests/vol_targeting_overlay_end_to_end.rs` | Vol-targeting overlay ≥ 1 bp divergence vs noop baseline |
| `crates/strategy/tests/vol_killswitch_overlay_end_to_end.rs` | Vol-killswitch overlay ≥ 1 bp divergence vs noop baseline |
| `crates/strategy/tests/latency_slippage_sim_e2e.rs` | v5 sim ≥ 1 bp divergence vs noop baseline (THIS feature's e2e) |
| `crates/strategy/tests/overlay_hygiene_gate.rs` *(meta)* | Audits that every overlay HAS a divergence test; not itself a divergence test for an overlay |

No new overlay/sizing modifier landed between 2026-05-27 v0.2.0 ship and
v0.3.0 brief author time. R6 scope confirmed at 3 + 1 meta.

## Alternatives considered

- **Lift `sim_slippage_cost` to `crates/exec` instead of a backtest-local
  module** — rejected. R-NR.5 explicitly says `crates/exec`, `crates/cost`,
  `crates/audit` library code is NOT touched. The helper is a
  backtest-only fill-accounting concern; lifting it cross-crate would
  add a tracked dep and require an exec-crate ADR.
- **Make `force_synthetic_bars` an env var** — rejected. CLI flags are
  introspectable and auditable in run logs; env vars are silent.
- **Hardcoded namespace allowlist in t1937 instead of front-matter
  parsing** — accepted. The path-based exclusion (`!contains(
  "v5-latency-slippage-sim-v0.2.0-anchor-migration")`) matches the
  Bash script's approach and avoids a new YAML parser dep in the
  reports test crate. Front-matter parsing is the upgrade path if a
  third namespace lands later.
- **New ADR for the per-path wiring contract; amend 0045 only for
  the resolver** — rejected. Both decisions are tightly coupled (the
  resolver only makes sense after the 6 paths emit canonical reports);
  one ADR for both is clearer.
- **Update SHA constants in t1937 instead of namespace-aware (Q4 = a)** —
  rejected per analyst recommendation and architect concurrence.
  Constants update is a 5-minute edit but re-breaks every future
  anchor migration. The resolver pattern is one-time cost, permanent
  fix. Mirrors the v0.2.0 Bash precedent.

## Consequences

**Mechanically enforced by**:

- `bash scripts/verify_anchors.sh` — PASS (68/68 or 63/63 depending on
  Q1) post-Wave C. The Bash namespace-aware logic was already shipped
  in v0.2.0; this ADR just adds the Rust mirror.
- `cargo test -p reports --test strategy_anchors_unchanged` — both
  `t1937_nine_strategy_anchors_unchanged` and a NEW
  `t1937b_canonical_strategy_anchors_unchanged` must PASS after Wave E.
- `cargo test -p strategy --test overlay_hygiene_gate` — confirms
  every overlay still carries a `*_end_to_end.rs` divergence proof
  (D6 inventory unchanged).
- `crates/backtest/src/scenarios/sim.rs` is the SOLE shared location
  for `sim_slippage_cost`; grep enforcement at tester M-FINAL
  (`grep -r "fn sim_slippage_cost" crates/backtest/src` must return
  exactly 1 line).

**What breaks if violated**:

- If a developer wires the simulator into a path WITHOUT calling
  through `sim.rs::sim_slippage_cost`, the helper-grep gate fails and
  R-NR.5 cross-crate-no-touch invariant is at risk (the helper might
  drift into `crates/exec`).
- If the namespace-aware resolver lex-sorts incorrectly and picks a
  noop report for a canonical anchor (or vice-versa), the t1937 test
  emits a body-SHA mismatch — same failure shape as the v0.2.0
  whitelist; orchestrator routes back to architect for root-cause.
- If `force_synthetic_bars` is added but the auto-detect at main.rs:982
  is NOT guarded by it, Group A re-emission silently re-picks up
  real-Binance data — Wave B Sharpe-delta table audit catches it
  via the data-source row in the report front-matter.

**Anchor migration scope**: post-Wave C, `evidence/anchors.toml` row count
goes from 68 → 68 (Q1=a Q3=a — same row count, 32 canonical SHAs
mutate in-place) OR 68 → 63 (Q1=b Q3=a — 5 Group A noop rows retire)
OR 68 → ~100 (Q3=b new pin — new canonical pin appended; superseded
v0.2.0 pin stays for archeology). Per ADR-0038 § D6.b/c, mutating
in-place canonical SHAs requires this ADR as the explicit re-emission
trigger (which it is). Anchor file edit is gated on Wave B re-emission
completing.
