## 2. Bug site (D6.b step 2)

`crates/reports/src/lib.rs:190-191` before the fix:

```rust
equity_delta:     realized_period.amount() + unrealized,
equity_check_sum: realized_period.amount() + unrealized,
```

Two character-identical expressions into the two fields `reconcile::compute`
subtracts, so identity 4 rendered `Δ = 0 | PASS` for every input. The row's label
advertised a `+ fees_delta` term that was computed nowhere — and with the wrong
sign, since fees reduce equity.

A second defect in the same bodies: `sample_equity_curve` held `equity_total` and
`cash_balance` at `cash` and set `realized_pnl` / `unrealized_pnl` to literal
zero. Its own doc comment called it a "v1+ orchestrator approximation". Identity 4
therefore had nothing real to compare **and** every published risk metric was
computed over a flat line.

| `reconcile.rs::t808_realized_period_is_wired_only_to_the_equity_row` | `realized` and `realized_period` are separate wires, and the perturbation's SIGN is asserted | trivially — one field fed both identities |

| `reconcile.rs::t808_mark_miss_unmeasures_only_the_headline_row` | `unmeasured` is excluded from `all_passed()` rather than counted as a pass | trivially — the third state did not exist |

**The missing test and the missing computation were hiding each other.** Every other row had a
one-cent FAIL-path test; identity 4 had none. The row that could never fail was also the row
nothing asserted could fail. Each of its three ledger-side terms now has its own perturbation,
so no term can go missing from the identity again without a named test going red.

The first is stronger than a test and is why identities 1–3 never had the defect:
`compute` derives their ledger side itself, and 4 was the only one that let the
caller supply both sides. The field is gone, so no caller can supply both again.

The second was RED-proven by temporarily restoring the constant-curve shape inside
`ledger_equity_curve` and re-running — `FAILED`, as the doc comment claims. The
probe was reverted from a file snapshot, not from git.

## 5. A third reconciliation state, because two contracts collided

A missing period-end mark zeroes `unrealized`, and T1006 V6 requires the report to
be produced anyway (warn + zero + footnote). Reconciling against a zero the report
itself substituted is this log's own failure mode. So `ReconciliationRow` gained
`measured`: identities 1 and 4 render `unmeasured` when the mark was unavailable,
are excluded from `all_passed()`, and 2/3 (realized only) stay measured. The
caller declares the condition via `unrealized_measured` rather than `compute`
taking a second argument, so the claim sits next to the data.

## 6. The clock pin — the second half of this re-emission

This pass produced **three** captures and discarded two. The first was
`d4b964c7…` / `5cb31966…`. **Those would have gone red the next day**, and locking them would
have been worse than the bug:

`ledger_equity_curve` samples the grid from `period_start` to `period_end`, and
every `ReportWindow` variant resolved `period_end` to `OffsetDateTime::now_utc()`.
A report rendered a day later over the same journal carries a longer flat tail, and
Sharpe/Sortino/Calmar are computed over the sampled return series, so they move
with it. Measured, not reasoned: `crates/reports/src/lib.rs`'s
`clock_sensitivity_tests::extending_the_window_without_new_movements_moves_the_ratios`
keeps the measurement executable, and records that max drawdown does **not** move
(a flat tail cannot deepen it) rather than lumping the metrics together.

This is bug-log `#158`: the two anchors had held for six months **by accident**.
A constant curve yields all-zero returns, and Sharpe is 0.0 for any sample count —
so clock-independence was a consequence of the curve carrying no information, and
the comment at the old `now` binding asserted the invariant ("front-matter only —
never in body") with nothing checking it.

The fix follows the CLAUDE.md coding rule that external I/O goes behind a seam so
tests can fake it. `reports::generate_at(now, …)` takes the clock as a parameter;
`generate` is a wrapper that reads the wall clock; the `report` bin exposes
`--now <RFC3339>` (a malformed value is `exit 2`, never a silent fall back to the
wall clock). The anchor tests pin `now` to the fixtures' `PERIOD_END_RFC3339` —
which the fixtures have carried since T816 for exactly this reason, and which the
tests used to compute and throw away because `generate` had no way to accept it.

The product keeps the wall clock. A month of genuinely flat equity is information,
so the sensitivity is correct for a real paper soak; it is only fatal for an
anchored body.

## 7. Landing, and the resolution trap (bug-log `#157`)

Landed, additively:

```
evidence/v1/operator-success-reports/reports/success-relock-20261107-report-sample-7d.md
evidence/v1/operator-success-reports/reports/success-relock-20261107-report-sample-90d.md
```

The superseded `success-fixed-report-sample-{7d,90d}.md` stay on disk byte-identical,
per D6.b — nothing deleted, nothing overwritten, the correction legible next to
what it corrects.

**The stamp is not cosmetic.** `verify_anchors.sh` resolves a scenario with
`find … | sort | tail -1` over FULL PATHS, and this machine runs `LC_COLLATE=C`,
so resolution is plain byte order. `success-relock-…` wins over `success-fixed-…`
because `r` > `f`. The obvious ISO name `success-20261107-…` would have **lost**
(`2` < `f`), leaving the gate hashing the superseded body. The re-emission
write-path (`report_scenarios.rs::reemit_if_opted_in`) refuses such a stamp rather
than warning.

**Near-miss worth recording.** The first run of that write-path passed a
repo-relative `REEMIT_DIR` and landed both bodies in
`crates/reports/evidence/v1/…` — `cargo test` runs with CWD at the *crate* root.
The log line printed the relative path, so it read as correct. Only hashing the
destination exposed it. The write-path now refuses a relative `REEMIT_DIR` and
prints the canonicalised path. Nothing was committed from that run.

How the re-emission is reproduced:

```bash
REEMIT_DIR="$PWD/evidence/v1/operator-success-reports/reports" REEMIT_STAMP=relock-20261107 \
  cargo test -p reports --test report_scenarios -- --nocapture
```

## 10. The second discarded capture — identity 4 as first written was wrong (`#159`)

`b6126992…` / `02719da7…` were correct, deterministic, clock-independent digests of a row that
**asserted something the ledger cannot witness.**

`audit::bootstrap` creates `income:unrealized_pnl` and `assets:position_mark:<ASSET>`, and
**nothing in this repository ever posts to either.** The accounts `journal.rs` writes are
`assets:cash:%`, `assets:position:%`, `equity:opening_balance`, `expense:fees:taker`,
`expense:llm:%` and `income:realized_pnl`. Unrealized P&L is computed at render time from the
mark source and never journalled. So

```
equity_delta = realized + unrealized - fees
```

compares a journal-walked left side, which cannot contain unrealized, against a right side that
does — unsatisfiable for any ledger with an open position whose mark moved, off by exactly
`unrealized`.

It passed on these two bodies because `build_ledger_{7d,90d}` hold twelve symmetric (Buy, Sell)
pairs, so `open_positions_at(period_end) = []` and the term is zero. **The replacement row was
passing for the same reason the tautology had been passing: a fixture in which the untested term
is zero.** `t1003_orchestrator_with_open_positions_computes_unrealized` caught it by returning
`ReportError::Reconciliation` — the new row doing its job on the one fixture that can exercise
it.

The row now reads, and labels itself,
`equity_delta = realized - fees - other_expense (journal only; excl. unrealized)`: a class walk
over `income:%`+`expense:%` on the left, three targeted account queries on the right
(`realized_pnl_since`, `total_fees_since`, and a new `other_expense_since` covering
`expense:%` minus `expense:fees:%`, because the live advisor posts `expense:llm:%`). Unrealized
stays reconciled by identity 1 against the published headline.
