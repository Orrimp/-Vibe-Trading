# Spec Audit — 2026-08-24 (weekly cadence — 4th post-BMAD-migration audit; 7-day window)

## Headline

**The window's own work disproved the project's most-cited non-negotiable, and the constitution
has not been updated to say so.** CLAUDE.md presents AD-2 — *"Anchors 119/119, byte-identical,
before AND after any change"* — as **the** regression gate. Bug-log **#93** (`2be1656`,
2026-08-22) proves it cannot be: `verify_anchors.sh` hashes the **committed report bodies** and
never re-derives them, so it is structurally blind to the code drifting away from the evidence.
The four tests in `crates/backtest/tests/determinism.rs` that *do* re-run a scenario went **RED**
— and were correctly marked `#[ignore]` rather than re-baselined. Net effect at HEAD: **`ANCHORS
PASS (119 / 119)` prints green while zero running gate can detect code-vs-evidence drift.** That
is a strictly worse position than last audit's F-A, and it sits *inside* the byte-frozen
constitutional clause rather than outside it.

Everything else is a strong window. **18 commits**, four CRITICALs closed with binding tests
(#71 side-blind cap, #76 inverted residual, #91, #92), the `--no-default-features` build fixed
**and given its own CI leg** — the only one of #92's three options that closes the
declared-vs-executed family — a same-day catch of #94 (the sizer wiring lost 74% of equity on its
first fixture), the #69 units ruled GROSS in ADR-0089 D7 with the ruling landing *against* the
evidence, and the dev/test disk footprint capped after `target/debug` reached 155 GB. Mechanical
lint **PASS(0)**, anchors 119/119, ADR registry clean at 89↔89.

But last audit's **P1 F-A is untouched**: `check_no_clocks_in_ui_tests.sh` is still RED at HEAD,
now **96 days**, and still only **2 of 9** gate scripts are wired into CI or the pre-commit hook.
Two new findings this run, both in the same family: the **bug-log's own `Status:` lines are stale
on 6 entries** while the rulings sit in the same file's bottom Changelog (F-E), and **the previous
audit note was never committed** — `audit-2026-08-17.md` is untracked in the working tree (F-F).

Read this as: **the engineering is excellent and the disclosure discipline is the best in the
repo's history — but the project's written constitution now overstates what its gates guarantee,
and three of this audit's findings are about instruments that report on themselves.**

## Findings

### F-D — NEW (P1). AD-2 as written overstates what the anchor gate can prove, and the only gate that could see the difference is now `#[ignore]`d

CLAUDE.md § Non-negotiables:

> **Anchors 119/119, byte-identical, before AND after any change (AD-2).**

Bug-log **#93** (`2be1656`, 2026-08-22) establishes that this measures immutability, not
reproducibility:

```
verify_anchors.sh   SHA of the COMMITTED report bodies   -> cannot see drift
determinism.rs      SHA of a FRESHLY RE-RUN scenario     -> the only gate that can
```

Four tests in `crates/backtest/tests/determinism.rs` re-run a pinned scenario and compare the
body-SHA to a literal. They are **RED at HEAD**:

```
top10-2023-1h-momentum
  expected 0f6f6eb8…  (pinned; also present in evidence/anchors.toml)
  got      b655e5e7…  (what the code produces today)
```

…and `verify_anchors.sh` printed `ANCHORS PASS (119/119)` in the same moment. Both are correct;
they measure different things. Bisect against `83378c5` shows they failed *before* #67/#71/#75/#76
landed — those fixes moved the numbers further, they did not cause the divergence.

**The handling was exemplary and is not the finding.** The four tests were marked
`#[ignore = "known-red pending the 1-26 re-lock: … do NOT re-baseline"]`
(`determinism.rs:744, 760, 787, 803`) with the reasoning inline, routed to story 1-26 as AC7, and
kept runnable (`cargo test -p backtest --test determinism -- --ignored`). Re-pinning would have
been bug-log #77's exact failure. `0582a5b` then went further and *re-measured* the four pins to
prove they are not part of D1's movement. That is the right call at every step.

**The finding is the constitutional residue.** Three concrete consequences:

1. **At HEAD, no *running* gate can detect code-vs-evidence drift.** The byte gate structurally
   cannot; the four re-running tests are ignored. This is a strictly worse position than the
   window opened with, and it is invisible from CI, which reports green.
2. **CLAUDE.md and `evidence/anchors.toml`'s header still present the byte gate as the regression
   gate.** An agent entering this repo reads AD-2 and reasonably concludes 119/119 proves the
   research surfaces still reproduce. It does not, and has not for some time.
3. **`check_determinism_anchors.py` reports OK on 14 literals with 0 skipped** — it compares
   System 2's constants against System 1's rows (ADR-0045 §D6.1 mapping). It does not know four
   of the tests holding those constants no longer execute. Another green-and-unrun.

**Recommended shape.** This wants an **ADR + a CLAUDE.md wording change**, not a patch — the same
"decision, not fix" character as SC-5. Minimum honest edit: AD-2 gains a sentence naming what the
byte gate does and does not cover, and pointing at the re-running tests as the reproducibility
leg. Then 1-26 AC7 removes the `#[ignore]`s in the same commit that re-derives the pins, so the
flip is visible in the diff (already specified). Owner: **architect → operator**.

### F-E — NEW (P2). The bug-log's `Status:` lines are stale on 6 entries; the same file's bottom Changelog is right

`docs/dev-notes/bug-log.md` is the project's disclosure ledger and — by CLAUDE.md's own framing —
one of the surfaces where honest status reporting *is* the product. It now carries **two internal
sources of truth that disagree**: the per-entry `**Status**:` line, and the dated Changelog at the
bottom of the file. The Changelog is current. The Status lines are not.

| Entry | `Status:` line reads                              | Actual state at HEAD                                                    | Evidence                    |
|-------|---------------------------------------------------|-------------------------------------------------------------------------|-----------------------------|
| `#68` | OPEN — implement-or-drop decision rides 1-25 AC3   | **RULED: DROP** (2026-08-19)                                            | `0b247e4`; 1-26 AC1         |
| `#69` | OPEN — enforce-or-delete … rides 1-25 AC3/AC4      | **RULED GROSS** (ADR-0089 D7) **and WIRED** into `run_path`             | `d051e15`, `eac1edf`, `723ca74` |
| `#71` | OPEN — owned by story 1-25                         | **FIXED** — resulting-exposure cap + 7-case binding test                | `7884f52`; 1-26 AC1 "done"  |
| `#76` | OPEN (fix + re-run are anchor-impacting → 1-25)    | **CODE FIXED** — direction inverted, literal-value gate added; re-run still owed | `7884f52`; 1-26 AC1 "done" |
| `#91` | OPEN, LOW severity                                 | **FIXED** — landed once #92 unblocked it                                | `eb353b5`                   |
| `#92` | OPEN — manifest honesty applied 2026-08-15         | **RULED and FIXED** — types relocated, **CI leg added**                 | `eb353b5`, `ci.yml:131`     |

Mechanically: `7884f52` and `723ca74` *did* touch `bug-log.md` — they appended evidence blocks and
new entries — but neither rewrote the `Status:` header of the entry it fixed. `eb353b5` (#91/#92)
did not touch the file at all. The rulings for #69 and #92 were recorded in the bottom Changelog
by `d051e15`, which is why the file is *collectively* honest and *locally* wrong.

**Why this is a P2 and not a nit.** Every consumer of this ledger — the operator scanning for open
work, the next reviewer, and this audit — reads the `Status:` line first; it is the field the
template puts at the top of each entry for exactly that reason. Taken at face value the ledger
reports **15 OPEN**; corrected against the code, the genuinely-open set is **9**
(#67, #75, #78, #80, #81, #83, #88, #93, #95) plus five partials (#82 mechanism 2, #85, #87, #89,
#90). A 40% overstatement of open defects is the *benign* direction of this error — but the
mechanism is symmetric, and the same file would understate just as silently.

This is the project's own recurring class (**declared ≠ actual**) applied to its instrument for
recording that class. There is no gate: nothing compares a `Status:` line to the commits that name
its id, and `spec_lint` does not read `bug-log.md`.

**Fix shape:** a one-pass sweep of the six lines, plus a convention that a commit naming `#NN` in
its subject must update `#NN`'s `Status:` line or state why not. A cheap mechanical version is
possible — `git log --grep='#NN'` vs the entry's Status token — and would fit the existing
`scripts/` gate family. Owner: **orchestrator** (ledger is orchestrator-owned) → **dev** if the
check is built.
