## Step 2 — the bug site

Bug-log **`#67`**, fixed in **`11acd126`** (2026-08-16): *"the harness was booking a ~1% gain for buying
one symbol at another symbol's price — engine guard + per-symbol fill routing"*. It touched
`crates/backtest/src/engine.rs` (+20) and `crates/backtest/src/paper.rs` (+98) — **the engine below
every lane.**

Bisected, one commit either side, on the default invocation these gates use:

| commit | date | produces |
|---|---|---|
| `b3332d35` | 2026-08-15 | `0f6f6eb8…` — GOOD, reproduces the pin exactly |
| `11acd126` | 2026-08-16 | `b655e5e7…` — BAD, and the hash seen ever since |

So the pinned bodies were `#67`-contaminated and **these gates were red because the engine became
correct.** On `top10-2023-1h-momentum` the diff is 8 lines, all summary-table: trades 4809 → 592,
buys/sells 2406/2403 → 296/296, max drawdown 87.63 % → 14.34 %.

**The scoping error that hid it for six weeks** is the part worth keeping: every artefact excluded `#67`
because these scenarios "do not go through `run_path`". True, and irrelevant — a defect fixed *beneath*
the lanes cannot be bounded by naming lanes. The `t622_*` gates corroborate the mechanism from the other
side: single-symbol, green throughout, because "one symbol at another symbol's price" needs two.

## Step 3 — the would-have-caught tests

`#67` already had its RED-proven binding test (`crates/backtest/tests/portfolio_controls_bind.rs`, see
the 1-26 record). What was missing was a gate that could see the *evidence* go stale, and that is what
this pass built:

- **11 `R-REPRO` reproduction gates** (`determinism.rs`, `multi_pair_determinism.rs`) that re-run the
  producer and compare against the **anchor** — not against a second run of themselves, which is the
  `#113` trap the pre-existing `*_determinism` tests fall into.
- Each gate **declares its condition**: `assert_reproduces_with_flags(scenario, anchor, flags)`, where
  passing `&[]` is itself the declaration "this asserts the default, zero-sim-slippage condition"
  (`#123`).
- A missing precondition is reported **UNMEASURED and loud**, never as a silent pass (`#113` req 6) —
  and that path immediately found `#114`, a checkpoint guard that had never once succeeded.
- No gate writes into `evidence/` any more; all use `--reports-dir` to a tempdir (`#113`). This was not
  theoretical: a red `m3_*` run would otherwise have planted drifted bodies in the corpus and flipped
  `verify_anchors.sh` as a side effect of running a test.
- **All nine go through ONE path** (`assert_reproduces_with_flags`) — added 2026-09-27 after the
  verification run exposed that R-REPRO-1..4 used a debug binary and a panicking runner while 5..9 used
  release and the fallible one. One family, two unstated conditions: `#112`'s shape in my own code, two
  hours after documenting it. Bug-log `#124` also carries the diagnosis fix it surfaced — a killed
  process was reporting "the binary exited non-zero", a refusal the binary never made.

## Step 4 — the in-place landing

Operator-ruled 2026-09-26: proceed under D6.b (the same ruling as 1-26 — re-emit in place, never
bifurcate), plus ruling **(a)** for `top10-2023-fy-momentum-realdata`.

Each body was produced under **its own** declared condition — three binaries, run sequentially because
they share `target/`:

| condition | scenarios |
|---|---|
| debug, no features, CWD = tempdir | the 6 synthetic (momentum ×2, tcn-overlay ×2, pairs ×2) |
| debug, `--features candle`, CWD = workspace root | the 2 `m3` weights |
| release, `--features candle,realdata`, CWD = workspace root, no sim flags | the 6 default real-data |
| release, same, **`--sim-slippage-sqrt-alpha 1.0 --sim-slippage-sqrt-lookback-days 90`** | `top10-2023-fy-momentum-realdata` (ruling (a)) |

Every produced hash matched the earlier independent measurements exactly — a full reproduction under
declared conditions, which is itself the evidence that these bodies are deterministic.

**The landing constraint, honoured deliberately.** `verify_anchors.sh` resolves each namespace to a
*different* directory set, so a body is not free to live anywhere: a canonical row resolves from the
v0.4.0/v0.3.0 migration dirs, the sqrt row **only** from the v0.5.0 dir, and a noop row from the newest
match *outside* all v5 dirs by a lexicographic path sort. Targets were therefore established
**empirically** — for each row, the directory currently holding the file that satisfies it — rather than
from the resolver's prose. The 15 FAIL / 104 PASS check in Step 1 is what proves it worked.

Every re-emitted row's comment block records the declared condition, the cause, where the body landed,
and **the superseded numbers verbatim with their old SHA**, so the correction is legible beside what it
corrects.

**System 2 was pulled along in the same pass.** 15 in-test pins across two files, and every `#[ignore]`
attribute removed — these are live regression gates again. The two `m3` pins additionally had their
namespace corrected (`#122`: they build `--features candle` and were pinned to the generation *before*
the candle re-emit). `scripts/check_determinism_anchors.py` now reports **OK — 14 literal(s) match**,
i.e. System 2 == System 1 for every site it can see. (It cannot see 11 of 25 — that is `#115`, still
open, and it is why `#122` survived for four months.)

## What this re-lock leaves open

- **`#115`** — `check_determinism_anchors.py` is blind to 11 of 25 pin sites and reports "0 skipped".
  Its "OK" above therefore covers 14, not all. Highest-leverage open item: it is the gate that should
  have caught `#122`.
- **`#118`** — `sharpe-comparison-realdata` has no producer at HEAD; re-emitting is not available, so its
  two rows need a disposition decision. Same for `eth-yahoo-2024-1d-sma-cross`, whose anchored body
  carries a substring the current emit shape cannot produce.
- **The 4 off-anchor pins** (`btc-2023-1m-{macd-trend,rsi-reversion,bbands-mean-revert}` and
  `eth-yahoo-2024-1d-sma-cross`) — those `anchors.toml` rows still have **no** re-run coverage, while a
  test sitting next to each looks like it provides some.
- **50 anchored scenarios still have no re-run gate at all** — 34 θ-surfaces, 1 MC, 15 forecast/report
  binaries. The coverage audit records what each would need; the θ-surfaces are cheap (32 of 34 re-emit
  in 9–43 s) and the blocker there is the gitignored corpus, not compute.
