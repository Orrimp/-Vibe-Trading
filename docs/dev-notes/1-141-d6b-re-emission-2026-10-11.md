## Why a re-emission rather than a patch

`#141`: ADR-0089 D2 made the portfolio exposure cap all-or-nothing — on a breach the ENTIRE
rebalance is skipped and the book is left unchanged for that bar — and both the ADR and the
field's own doc call surfacing the refusal count *"the non-negotiable half of that policy"*, for a
stated reason:

> a silent skip reads exactly like a clean run, which is the failure class bug-log `#66` was.

It was never surfaced. `run_path` has counted it since `723ca742` (2026-08-23); the count was
dropped at `PathRunResult → IndexedPathMetrics`, the intermediate the per-cell aggregation sees,
so it reached no `CellResult`, no renderer, and no report body. Its only reader in the workspace
was the test proving it increments.

The consequence for the corpus is specific: **an operator reading any of the 34 regenerated
θ-surfaces cannot distinguish "the cap never bound" from "the cap refused rebalances and nobody
wrote it down".** For the momentum/MR lanes the first is true and the code says why (~0.30 gross
against a 0.50 cap). For the lanes the same doc says run hot — TS at ~90-100 % gross, the MN book
at ~60 % — the second was a live possibility that the artifact could not rule out.

Making the count visible changes the rendered body, hence the body-SHA, hence the anchor. That is
a re-emission by definition, which is why it needed a ruling rather than a commit.

## Step 3 — the RED-proven would-have-caught test

`crates/backtest/tests/param_sweep_e2e.rs::bug141_the_breach_count_reaches_the_body_and_a_zero_is_printed_too`

It asserts four things and was **probed RED in both directions**, with the restored code green
afterwards:

| probe | what was broken | which assertion fired |
|---|---|---|
| 1 | the surfacing block deleted entirely | *"a surface whose cells refused 3 and 4 rebalances must report 7 in its body"* |
| 2 | the line emitted **only when `breaches > 0`** | *"a surface with no refusals must SAY zero, not stay silent"* |

Probe 2 is the one that matters. A gate checking only the non-zero case would pass a renderer
that stayed silent on zero — and then a clean surface and an unsurfaced surface are byte-identical
again, which is the entire defect restored. **An unprinted zero and an uncomputed zero read the
same**, so the zero is printed explicitly.

The test also pins that the number is the SUM across cells (3 + 4 = 7, so printing one cell's
count fails), that the hot and clean bodies differ (so the printed value tracks the input rather
than being a constant), and that ADR-0089 D2's all-or-nothing semantics travel with the number —
a bare integer is not a disclosure if the reader must guess what a refusal did to the book.

## Step 5 — the negative invariant

**`#141` is additive REPORTING and changes no computation, so every regenerated body must be
byte-identical to its current anchored predecessor except for the inserted block.** Any numeric
movement would be a defect in this change, not a result — and that is the invariant, checked
mechanically per surface rather than asserted.

That check is the inverse of a normal re-lock's: 1-24 and 1-26 both expected numbers to move and
had to say how. Here a moved number is a bug.

### What the disclosure actually revealed, and it is not small

**The cap was binding on 18 of 34 surfaces, and no report had ever said so.**

| lane | surfaces | refusals per path-run | share of rebalance opportunities refused |
|---|--:|--:|--:|
| `ts-horizon-daily` | 2 | ~29 | **7.96 % – 8.18 %** |
| `ts-momentum` | 2 | ~324 – 347 | 3.70 % – 3.95 % |
| `mn-basisperp` | 4 | ~321 – 330 | 3.66 % – 3.76 % |
| `ts-horizon-4h` | 2 | ~82 | 3.72 % |
| `mn-basis` | 4 | ~146 – 174 | 1.67 % – 1.99 % |
| `mn-funding` | 4 | ~124 – 140 | 1.42 % – 1.59 % |
| momentum / MR / carry / basis-reversal | 16 | 0 | 0 % — the cap never bound |

The 16 zeroes are the expected reading and are now **printed** rather than merely true: at
`FIXED_FRACTION` 0.10 with `k_long` 3 those grids target ~0.30 gross against a 0.50 cap. The
18 non-zeroes are exactly the lanes `montecarlo.rs:114` predicted would run hot — TS at
~90-100 % gross, the MN book at ~60 % — and they are the surfaces where a reader previously had
no way to tell a clean run from a throttled one.

**A consistency check that passes:** each `fee00bps`/`fee05bps` pair reports an *identical*
refusal count. The cap decides on notional and is evaluated before fees, so fee tier must not
change which rebalances are refused — and it does not.

### How to read this, stated carefully

What did NOT change: any number. The cap was always binding on those 18 surfaces and the anchored
results always included its effect. This re-emission disclosed a fact about the corpus; it did not
alter the corpus's arithmetic.

What a reader should now do differently: on those 18 surfaces, 1.4 % – 8.2 % of rebalance
opportunities were refused outright, so part of each arm's measured behaviour is
constraint-driven. That bears on **why** an arm underperformed, not on **whether** it did — and
`exposure_cap = 0.50` is a hashed `grid_def` field, so these arms were measured **as specified**,
under their own declared configuration. The era-qualified ship-passive conclusion rests on arms
evaluated against their own declared limits, which is the honest basis for it; the 0-of-156-cells
control in `evidence/v2/harness-relock/ERRATA.md` § 4.1 is unaffected because no number moved.

What would be dishonest is to leave it at that without naming the consequence: **the TS lanes in
particular were never measured at their intended exposure.** They target ~90-100 % gross against a
cap of 0.50, so the cap wins routinely by construction. Whether that configuration should have
been 0.50 for those lanes is a question this record does not answer and should not pretend to —
it is now visible, which is all `#141` claimed to deliver.
