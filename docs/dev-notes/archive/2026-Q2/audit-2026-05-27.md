medium confidence).**
`spec/product.md` line 381 states: `backtest engine: paper-fill MatchingEngine
with bps: 2 slippage and 0.04% taker fee`. With `v5-latency-slippage-sim`
shipped 2026-05-27, the canonical friction profile is now `LatencySlippageSimConfig
{ latency_ms_min: 30, latency_ms_max: 80, slippage_bps: 8 }` under namespace
`v5-realdata-medium-2026-05` (ADR-0043, ADR-0045). The product.md prose still
reflects the pre-v5 fixed `bps: 2` value. This may be an intended historical
reference (product.md documents what was true at v0 week 2) or it may be stale
(a reader would expect the canonical friction to be updated). Confidence: medium.
Owner: analyst (annotate or update product.md § Backtest to reference v5 sim as
the current friction model). Note: product.md's line 381 is in a "week 2" progress
narrative, so it may be deliberately historical — analyst to judge.

**2. ADR-0043 D2 deviation: Murmur3-style finalizer, not ChaCha20Rng (known,
documented).**
ADR-0043 D2 commits to "seeded ChaCha20Rng sub-stream" for replay determinism,
but the backlog ship summary for v5 v0.1.0 records a D2 deviation: "ChaCha20Rng
replaced [by Murmur3-style finalizer] for hot-path perf" with the change accepted
via ADR-0043 Changelog amendment. The INV-DETERMINISM-RNG-001 invariant in
trace.toml (`"All RNG must be seeded with ChaCha20 from a config-supplied seed"`)
covers the strategy/backtest RNG — it is unclear whether the v5 sim's per-fill
hash counts as "RNG" under this invariant. If the hash is deterministic and not
used for randomness (it is a deterministic noise function keyed on order_id), it
may not violate the invariant; if it is considered RNG, the invariant is violated.
Confidence: low-medium — the ADR amendment may have cleanly carved out the
exception. Owner: architect to confirm that INV-DETERMINISM-RNG-001 scope
excludes deterministic hash functions vs ChaCha20.

**4. Money-math invariant — consistent.** ADR-0043 slippage arithmetic uses
