# Story 1-29 — ADR-0038 § D6.b re-emission record, 2026-10-01

The two `recalibrate-sigma-train` rows, re-emitted because the one sentence in their bodies that
asserts the run was read-only names the only file the run wrote (bug-log `#134`).

This is also what unblocks them: `#128e` had these two rows down as the single genuinely
ungateable pair in the forecast-binary family, on the grounds that `--anchor-dir` reaches the hashed
body and so no tempdir reproduces the anchor. It does reach it — through this sentence. Fixing the
sentence removes the dependency, so the correction and the unblocking are one change, not a trade.

## The five steps

### 1. Affected anchors, enumerated exhaustively

Derived from the criterion rather than listed by hand: every `[[anchors]]` row whose body is produced
by `recalibrate_sigma_train`. That is **two scenarios × two namespace rows each = 4 rows**, all
carrying the same SHA per scenario (verified: `anchored_sha` asserts duplicate rows agree, and it
passes for both).

| scenario | namespace rows | SHA before |
|---|---|---|
| `recalibrate-sigma-train-bs1` | `… + noop-baseline`, `… + v5-realdata-medium-2026-05` | `baa658fb…50336ad9` |
| `recalibrate-sigma-train-bs2` | same two | `bfa8104a…954b47e0` |

Nothing else is affected. `render_report` is private to the bin and has exactly one call site; the
changed parameter is used in exactly one place in the function body (verified by reading, and the
tripwire in step 3 re-verifies it on every run).

### 2. The defect, cited

`crates/forecast/src/bin/recalibrate_sigma_train.rs:457`, fed from `:686`:

```rust
writeln!(&mut body, "- Read-only against `{overlay_path}` original safetensors.")
```

and `overlay_path` at `:628`:

```rust
let overlay_path = args.anchor_dir.join(&overlay_filename);   // {prefix}-{sha}.metadata.recalibrated.json
write_overlay(&original_metadata, sigma_train_recal, &overlay_path)?;   // :631 — the run WRITES it
```

Rendered, in both anchored bodies:

```
- Read-only against `crates/forecast/checkpoints/anchors/tcn-bs1-d1c3696d….metadata.recalibrated.json` original safetensors.
- Read-only against original `.metadata.json` (no mutation).
```

The second line is correct and needs no path. The first was meant to name the safetensors sibling and
was handed the write target. Two things wrong in one sentence: it calls a file read-only that the run
created three lines earlier, and it calls a JSON metadata overlay *safetensors*.

The bin's own header doc states the contract correctly — *"NO mutation of … `.safetensors`"*,
*"Exactly two filesystem-write calls: 1. `std::fs::write(overlay_path, …)`"*. The contract is right and
the code honours it. Only the **report** misstates it, which is the worst of the three places for it to
be wrong: the report is what a third party reads, and the anchor gate has been defending the sentence
since 2026-05-21.

### 3. The would-have-caught tests, RED-proven

Both in `crates/forecast/tests/recalibrate_sigma_train_readonly.rs`.

**`report_is_handed_the_read_path_not_the_write_path`** — cheap, always runs. Walks the
`render_report` call site and asserts it receives no `anchor_dir`-derived value and does receive a
`.safetensors` path. **Measured RED against unmodified `HEAD`** before the fix:

```
#134 regression: render_report is handed `overlay_path`, which is `args.anchor_dir.join(…)` —
the file the run WRITES. It reaches the hashed body through the "Read-only against …" note,
which then names the only artefact the run created.
```

GREEN after. It walks a *different* file than its own, so it needs no `concat!` self-match guard
(`#133`); its non-vacuity guard is that a missing or renamed call site **fails** rather than passing
over a file it no longer understands.

**`body_is_anchor_dir_invariant`** — the real proof, `#[ignore]`d at ~36 min. Two runs per scenario
into two **different** anchor-dirs must produce the same body-SHA. This is the invariant that both
proves the fix and unblocks the gate, so one assertion carries both. It additionally compares the
committed checkpoint directory **byte for byte** across four real runs — the read-only assertion
`#135` had nowhere to put, because the existing guard only ever ran `--help`.
