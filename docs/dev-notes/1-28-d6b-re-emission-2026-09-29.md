# Story 1-28 — ADR-0038 § D6.b re-emission record, 2026-09-29

34 θ-surfaces re-emitted so the corpus can say two things it could not say before: **whether a path
was ruined**, and **whether a fill was a decision or a forced exit**. No number moved.

## The five steps

### 1. Affected anchors, enumerated exhaustively

All **34** θ-surface rows — every surface the renderer touches, because the ruin line is emitted above
the table on the path all six table shapes pass through. Not MN-only: a tripwire covering 12 of 34
surfaces misses 22 by construction, and the ambiguity being fixed is family-independent.

The member list is **derived**, not written down: `scripts/relock/surfaces.tsv`, the same manifest
story 1-26 used, cross-checked against the gate's own resolution (`verify_anchors.sh --explain`) so
each surface lands in the directory its anchor actually resolves to. All 34 resolved; the landing
script aborts rather than landing a partial corpus if any does not.

### 2. The defect, cited

- **Ruin** — `crates/backtest/src/stats/mod.rs`, previously three inline copies at
  `mc_harness.rs`, `bin/param_robustness_sweep.rs` (twice). Every equity value `<= 0` is clamped to
  `1e-6` before the metric calls so `compute_sharpe_hourly` cannot return NaN (ADR-0051 D2). The clamp
  is correct and stays. The defect is that `e <= 0` was evaluated at three sites and recorded at none,
  so afterwards a path that lost everything and a path that lost 99.9 % are the same number, and
  `p95_maxdd` at ~100 % is the signature of ruin **and** what a merely catastrophic path prints
  (bug-log `#127`).
- **Fill provenance** — `crates/backtest/src/scenarios/montecarlo.rs`: `trades` was incremented both
  for a real fill and for every synthetic buy-to-cover leg of an M-DEV-3 maintenance-margin
  liquidation. One counter, two events. Bug-log `#110` shipped a legend saying so — *"MN turnover is
  not directly comparable … read it next to the liquidations column"* — because the report could not
  make the distinction. It can now, so the caveat is replaced by the numbers.

### 3. The would-have-caught tests, RED-proven

- `stats::clamp_witness_tests::a_ruined_path_is_reported_as_ruined_and_a_merely_bad_one_is_not` —
  asserts the distinction the three clamp sites could not make.
- `stats::clamp_single_definition_test` — a source walk asserting the clamp literal exists at exactly
  two sites, naming every site on failure, with a non-vacuity floor. **Probed**: a fourth copy inserted
  into `mc_harness.rs` → RED naming `mc_harness.rs:294`; restored → green. On its first run it reported
  THREE sites and the third was its own search string, now split so the detector cannot match itself.
- `mn_spread_divergence_e2e::a_forced_cover_is_counted_separately_and_never_as_a_trade` — **this one
  could not be replaced by evidence.** The live corpus contains **zero** liquidations since the `#71`
  fix took 2210 events to 0, so `cover_fills` reads 0 on every surface below and its ability to be
  non-zero cannot be demonstrated from the corpus. A 3-symbol LongShort fixture shorts the worst
  performer and moves it tenfold; the liquidation fires (1 event) and the counter reports it.
  **Probed**: reverting the increment to `trades` → RED with the message naming the always-zero column
  the test exists to prevent. A long-only control on the same prices asserts zero covers and non-zero
  trades, so a counter that merely mirrored `trades` would not pass.

### 4. Protocol and landing

ADR-0038 § D6.b, **decided by the orchestrator** under the standing authority of 2026-09-29 rather
than escalated — this story's AC5 had been written as an operator entry gate, which it should not have
been. The precedent is `#110`, which re-emitted these same MN surfaces under D6.b while adding the
`trades` and `funding` columns: the same shape. Where it strains is stated rather than hidden: the
ruin half is an observability addition, not a wiring-bug fix, and § D6.c does not exist. Using the
ratified protocol and naming the strain beats inventing one to fit a single story.

Landed in place — new timestamped bodies beside their predecessors in the same directories, which is
what "in place" has always meant here (the resolver takes the newest match).

## What the new columns say, and what that means

**Ruined paths: 0 on all 34 surfaces.** This confirms from the producer what was measured from the
corpus days earlier: zero cells sit at `p95_maxdd >= 99.9 %`. The column is a **tripwire, not a
correction** — nothing in the current evidence was being misread, and the guard is now in place before
the next surface that would be.

**`cover_fills`: 0 on all 12 MN surfaces**, with `liquidations` also 0 since the `#71` fix removed the
absorbing state. So the split is a no-op on today's numbers — `trades` is unchanged because there were
no covers to subtract — which is precisely why step 3's fixture test was not optional.

The denominators were verified against the manifest's own `--paths` values rather than an assumed
constant: **34 surfaces, 0 deviations.** (My first check assumed 200 paths everywhere and flagged two
`carry-horizon-daily` surfaces; they run at 1000 paths and the reported `6000` was correct. The check
was wrong, not the code.)
