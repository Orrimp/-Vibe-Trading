### Gate 2 — FAIL-on-pre-fix dry-run (CRITICAL — INCONCLUSIVE)

**Finding: the test suite for Gate 1 is a mechanism-proof suite, NOT a production-call-through suite. It does NOT catch a regression where runner.rs reverts to direct-await.**

The orchestrator brief requires: "Temporarily revert the rt.spawn change at runner.rs:843-847. Run the test → it MUST panic/fail."

Dry-run performed:
- All 3 tests in `lab_runner_http_offexecutor_e2e.rs` were inspected. None call `spawn_lab_run`, `preload_yahoo_bars`, or any production function from runner.rs.
- Test 1 (`spawn_blocking_without_rt_spawn_panics`) calls `tokio::task::spawn_blocking` directly within its own `futures::executor::block_on` context — independent of runner.rs state.
- Test 2 (`spawn_blocking_with_rt_spawn_does_not_panic`) calls `handle.spawn(async { tokio::task::spawn_blocking(...) })` with a locally-scoped `handle` — independent of runner.rs state.
- If runner.rs:843-847 were reverted from `rt.spawn(...)` to a direct `preload_yahoo_bars(...).await`, none of the 3 tests in `lab_runner_http_offexecutor_e2e.rs` would change result. They would all still PASS.

**The test theater criterion is met**: the new HTTP-path test does NOT fail when the fix is reverted.

**What the tests DO prove correctly:**
- The broken primitive (`spawn_blocking` from `block_on`) panics (Test 1 — confirmed live above: 3/3 PASS including this assertion).
- The fix primitive (`rt.spawn()` wrapping) resolves cleanly (Test 2 — confirmed live).
- `abort()` cancels a JoinHandle (Test 3 — confirmed live).

**What the tests FAIL to prove:**
- That the production runner.rs `spawn_lab_run` function uses `rt.spawn()` for `preload_yahoo_bars`. A future developer could accidentally remove the rt.spawn and the test suite would not catch it.

**Note on lab_runner_cold_cache_fetch_e2e.rs validity after RS2:**
The `lab_runner_cold_cache_fetch_e2e.rs` test (hotfix-1 gate, 3/3 PASS) was written to validate the `rt.enter()` guard pattern in `fetch_with_backoff`. RS2 removed those guards from `fetch_with_backoff`. The `cold_cache_fetch_e2e` tests use `std::future::ready(())` as the inner future, not actual `fetch_with_backoff` production code. The test docstring says "Regression guard: if the rt.enter() guard is removed from fetch_with_backoff, the same futures::executor::block_on context would panic." But since RS2 already removed those guards (correctly — the function now runs on-runtime), this regression guard is vacuously true and the test's stated invariant no longer applies to production code.

**Routing consequence for INCONCLUSIVE:** Per the orchestrator's verdict cell: "INCONCLUSIVE — the new HTTP-path test does NOT fail when you revert the fix (test theater — doesn't actually exercise the reactor-context requirement)." HANDOFF → developer to add a production-call-through gate. Suggested pattern: inline `spawn_lab_run` with a real `SlowFakeYahooBarSource` (that calls `tokio::task::spawn_blocking`) under `futures::executor::block_on`; assert no panic.
