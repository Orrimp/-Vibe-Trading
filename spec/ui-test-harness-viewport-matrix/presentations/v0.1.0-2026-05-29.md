# UI test harness — viewport matrix v0.1.0 — release

## TL;DR

- All non-Charts widget tests under `crates/ui/tests/` now render at three viewport slots (floor 1280×720, typical 1920×1080, operator 3360×1890 ×2.0) instead of one — 22 in-scope fixtures expanded to triple coverage, **51 + 10 PASS + 15 architect-approved ignored** across two consecutive runs with zero baseline byte deltas.
- Regression-class defender: any future widget refactor that drifts the renderer (the exact failure mode that birthed the bootstrap — invisible tooltip at 3360×1890 that rendered fine at 1280×720) now fails CI on the first PR instead of slipping through the single-viewport gate.
- Tester `VERDICT → PASS` at commit `420850e` — 9 mandatory gates green; **56 baseline PNGs** committed (48 top-level + 8 render_snapshots) totalling **15 MB** (well below the K2 100 MB ceiling); P-VPM-1 falsification probe PASS confirms baselines are slot-NAME-keyed, not slot-INDEX-keyed.

## Why

The bootstrap shipped Charts at three viewport slots in 2026-05-12 because a real production incident (tooltip invisible at the operator's 3360×1890 hardware while rendering fine at 1280×720 dev boxes) slipped through a single-viewport snapshot gate. Every non-Charts widget — panels, modals, status bar, agent feed, debug screen — was still gated at one viewport, leaving the same failure class open. The Pick A Wave 1 trifecta direction (2026-05-29) promoted this as the mid-cost durable pillar (~3-4 dev days actual): every UI feature shipped from this point inherits three-viewport snapshot coverage by default, and viewport-only bugs become CI-detected on the first PR. Multiplies with the sibling-shipped `visual-fail-html-reporter v0.1.0` (commit `d336b98`, 2026-05-29) — the matrix produces more failure surface; the HTML reporter closes the agent-facing failure-artifact gap for those failures. See [`spec/ui-test-harness-viewport-matrix/feature.md`](../feature.md) § Why and [`spec/dev-notes/pick-a-test-infra-trifecta-2026-05-29.md`](../../dev-notes/pick-a-test-infra-trifecta-2026-05-29.md).

## K3 caveat — cross-platform/cross-time determinism (operator MUST read)

The 56 baselines were **generated on the architect's Apple Silicon host in a single build session** (commit `ec79ac0`, ~14:00 local). Tester verified they re-render byte-identical on a second run on the SAME host (K3 single-canonical-host contract holds). The bootstrap M-T1 dry-run already empirically confirmed that re-rendering Charts baselines on a DIFFERENT build session — even on the same host — produces byte-mismatches at the rgba-bytes level (PNG sizes match within <1 KB; bytes do not). **This means:**

- If you run `cargo test -p ui --test visual_snapshots ... live` on the SAME machine that committed `ec79ac0`, you will see 51/51 PASS.
- If you run it on a DIFFERENT machine (Intel Mac, Linux CI runner, different architect's box) you will likely see byte-mismatches — NOT a real regression, just the K3-deferred cross-machine determinism gap.
- The proper close on K3 is the **`ui-test-harness-ci`** Queue feature — a canonical headless GitHub Actions Apple Silicon runner re-anchors the baselines workspace-wide and `.gitattributes` is amended for image-compare's perceptual-tier tolerance. Out of scope for v0.1.0.

For now: trust the tester's two-run determinism; treat any cross-machine drift as the K3 known gap, not a regression.
