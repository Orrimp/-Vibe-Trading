# v5 v0.5.0 — square-root market-impact model — sprint review

## TL;DR

- **SquareRoot market-impact model ships** (`cost = α · √(Q/V)`; Almgren-Chriss 2001 — the academic-canonical alternative to the v0.4.0 linear-bps model). Closes the ADR-0043 § D3 deferred-from-v0.1.0 promise; v5 anchor-migration arc now spans engine → canonical config → per-path wiring → candle/realdata coverage → model-quality upgrade.

Surfaced by Q-D1+Q-D2 operator-decide brief, not by the unit-test layer — pattern reference for future model-overlay sign-off.

## The bug fix (highlight — load-bearing for ship integrity)

Caught during Wave D, mid-implementation, by the Q-D1+Q-D2 operator-decide brief.

**Pre-fix state** (Waves A+B+C+F shipped clean at `e09e599`):

```rust
// crates/backtest/src/scenarios/sim.rs — pre-fix
pub fn sim_slippage_cost(
    qty: Decimal,
    fill_price: Decimal,
    side: Side,
    cfg: &LatencySlippageSimConfig,
    volume_usd: Decimal,   // <-- every call site passed Decimal::ZERO
) -> Decimal { ... }
```

Every call site (momentum, tcn_overlay, tcn_overlay_weights, patchtst_overlay_weights, pairs, garch_vol_target_overlay, regime_dispatcher) was passing `Decimal::ZERO`. The `apply_slippage_sqrt` body had a defensive early-return for `V = 0` (treating it as zero-slippage, since `Q/0` is undefined). Result: the SquareRoot model would have returned **zero slippage on every fill** — structurally identical to a no-op overlay. Wave A's 14 unit tests on the cost-crate layer all passed because they fed non-zero V directly; the wiring layer was untested end-to-end against a non-zero V.

**Post-fix** (lines 52-94 in `crates/backtest/src/scenarios/sim.rs`):

```rust
pub fn sim_slippage_cost(
    qty: Decimal,
    fill_price: Decimal,
    side: Side,
    cfg: &LatencySlippageSimConfig,
    symbol: &Symbol,           // <-- now takes the symbol, looks V up internally
) -> Decimal {
```

`apply_slippage_sqrt` now resolves V via `cfg.volume_usd_per_symbol.get(symbol).copied().unwrap_or(Decimal::ZERO)`. 7 scenario call sites updated to pass `symbol` instead of `Decimal::ZERO`.

**Evidence the fix is wired** (verified by tester):
- Signature grep on `crates/backtest/src/scenarios/sim.rs` shows `symbol: &Symbol`.
- TCN-overlay-2023 sqrt equity = $10,105.53 vs linear baseline = $77,001.73 — divergence $66,896.20, >> 1 bp threshold (the CLAUDE.md non-negotiable for overlay e2e tests).
- New unit test `sqrt_missing_symbol_fallback_zero` covers the defensive V=0 path explicitly.
- All 7 prior sqrt-related unit tests still PASS.

**Pattern reference** — this is the same failure mode as the v3-volatility-forecaster 2026-05-22 no-op overlay discovery (CLAUDE.md non-negotiables now require e2e baseline-divergence tests for every overlay from day 1). The v5 v0.5.0 model-quality upgrade falls under the same gate; without the e2e divergence asserted at the reporting layer, the bug would have shipped silently with byte-stable but semantically empty SHAs.

## Why

ADR-0043 § D3 (v0.1.0 engine ADR, shipped 2026-04) carried an explicit deferral:

> "Square-root market impact (`impact ∝ sqrt(notional / depth)`) needs an order-book depth estimate that isn't available in our Parquet bar data at v0.1.0. Adding it requires an order-book ingest module — out of scope."

Two facts erased that premise between v0.1.0 and v0.5.0:

1. **Daily-volume USD is already on disk** — the Binance parquet feed (`data/binance/<SYM>/<YEAR>/`) carries `volume` per OHLCV bar; a 90-day trailing mean of `volume × close` is the Kissell 2014 ch. 3 § "Volume-based impact" production-grade surrogate for L2 depth when order-book ingest is unavailable. No new data source, no new on-disk artifact (Option A architect decision; the parquet feed is already revision-pinned at `REVISION.toml` SHA `3a8b96…bfc7`).
2. **Linear bps under-prices high-turnover risk** — v0.4.0 TCN-realdata reported ~6,200 fills at flat 8 bps per fill, a model with no liquidity feedback. SquareRoot penalizes large fills relative to daily volume, which is the real-world failure mode the model is supposed to expose. The Sharpe-delta table below confirms the directional effect.

The operator's M-OD 2026-05-29 ratifications (`Q1=(a) α=1.0`, `Q2=(a) 90-day Binance parquet`, originally `Q3=(b)` later superseded by `Q-D1=(a)`) close the model-quality gap with no v0.6.0 follow-on cleanup brief queued.

### H1 — sqrt drag ≥ 2× linear drag on high-turnover scenarios

**PASS.** TCN-overlay-realdata-2023: linear drag = $22,998; sqrt drag = $89,895. **Ratio = 3.91×**, well above the ≥ 2× threshold. Tester verified the ratio independently from report equity values.

### H2 — sqrt drag ≈ linear drag on low-turnover scenarios (≤ 30 pp threshold)

**PARTIAL.** Two scenarios in the falsifier scope:

- **vol-target-overlay-2023** (4,585–5,129 fills): Δ = **+8.18 pp** — sqrt is actually LESS costly than linear here, because the GARCH overlay filters the signal set and the reduced Q per fill benefits from the sqrt model's lower per-fill impact at low Q. Within the 30 pp threshold → PASS.
- **patchtst-overlay-2023** (3,187 fills): Δ = **-84.44 pp** — outside the 30 pp threshold → FAIL. Documented as **medium-turnover architect-known exception** (the H2 ≤ 200 fills definition does not cover the 3,187-fill PatchTST signal; this is not an unknown surprise). No escalation needed.

### H3 — byte-identity determinism across 2 independent runs

**PASS.** Developer's full 9/9 × 2 = 18-report set was submitted; tester spot-checked 3/9 (momentum, tcn-overlay-2023, regime-dispatcher-2024) — all byte-identical between run-1 and run-2. K2 f64-conversion-boundary contract (architect M-T1 § D-T1.3) holds: `Decimal::to_f64` → `f64::sqrt` (IEEE-754 AArch64 `fsqrt`) → `f64::round_ties_even` → saturating-u32 → back to Decimal. No cross-run drift.

### K1 surprise scan — `sharpe(sqrt) < 0 ∧ sharpe(linear) > 0`

**1 sign-flip, 0 unexpected.**

- **patchtst-overlay-2023** flips from linear +5.97% → sqrt -78.47%. This is exactly the H1 mechanism (3,187 fills × high Q/V → sqrt drags hard), inside the pre-disclosed patchtst "medium-turnover architect-known exception" scope. Tester explicitly did NOT escalate this — it is a model-sensitivity event within the documented exception, not an unknown K1 surprise.
- All other 8 scenarios already had negative linear returns; sqrt makes them more negative without sign change.
