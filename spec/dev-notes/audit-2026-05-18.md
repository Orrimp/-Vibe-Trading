## Soft contradictions (LLM-judged — verify before acting)

Sweep covered five cross-cutting topics drawn from CLAUDE.md
non-negotiables and architecture invariants. Each topic was checked
against `spec/product.md`, `spec/architecture.md` (+ its
`architecture/*.md` shards), and representative `feature.md` files.

**1. Money math (Decimal vs f64).** No contradiction found.
`architecture.md:33` and `ADR-0003` declare "Money math uses
`rust_decimal::Decimal`, never `f64`." `v0-paper-sma/feature.md:97–102,
508–541` consistently use `Money<C>(Decimal)`, `Price(Decimal)`,
`Quantity(Decimal)`. Downstream features (`per-symbol-position-accounts`,
`real-mtm-unrealized-pnl`, `v1-cross-sectional-momentum`,
`v15a-mean-reversion-pairs`, `v2-llm-strategy`) extend the same types
without re-introducing `f64`. Clippy lint `float_arithmetic` rooted at
`trading_core` enforces this in CI per the v0 design. **Confidence:
high.**

**2. RNG seeding.** No contradiction found.
`architecture/11-regression-gate.md:61–63` and `ADR-0002` mandate
`ChaCha20Rng::from_seed(...)` and explicitly forbid `thread_rng()`,
`OsRng`, and `SystemTime`-derived seeds. UI fixtures in
`architecture/06-ui-and-cockpit.md:394, 465–471` and feature files for
`ui-test-harness-bootstrap` use the same RNG with deterministic seeds.
The Q6 footnote at `06-ui-and-cockpit.md:592–604` adds an `XOR-stir`
derivation step but it remains `ChaCha20Rng::from_seed([u8; 32])` —
not a divergent claim. **Confidence: high.**

**3. Timestamps in anchored bodies.** No contradiction found.
`architecture/11-regression-gate.md:40–45` documents that
front-matter holds run-varying metadata (`generated:`, `wall_clock_s`,
host, pid, git commit, data-source path) and that body-only SHA-256
hashing is correct. `anchors.toml` header comment repeats the contract.
Past leak (`wall_clock_s: f64` into the body) is described as a
historical bug, not a current state.  **Confidence: high.**

**4. No clocks in UI tests (V4 determinism gate).** No contradiction
found. `ui-test-harness-bootstrap/feature.md:253, 309, 377` defines V4
as `scripts/check_no_clocks_in_ui_tests.sh` — grep gate for
`SystemTime::now`, `Instant::now`, `thread_rng`,
`UtcOffset::current_local_offset` with `// CLOCK-OK:` whitelist
markers. Cited as PASS in
`ui-test-harness-bootstrap-2026-05-12.md` presentation; no other
feature claims a contradictory test-time clock policy.
**Confidence: high.**

**5. Sub-agent capability boundary.** Mild *clarification gap*, not a
strict contradiction. `AGENT.md:484–530` declares the orchestrator
exclusively owns `cargo run --bin cockpit` with a live window,
`screencapture`, `osascript`/`cliclick`, "concluding the bug is X from
live-app instrumentation," and adjudication between sibling sub-agents.
`AGENT.md:498` lists `spec_lint.py (via uv run or python3 ≥ 3.11)` as
sub-agent allowed. Two soft issues:

- The spec-auditor agent definition (`.claude/agents/spec-auditor.md`)
  is itself a sub-agent that runs `scripts/spec_lint.py` and `Bash` —
  consistent with the boundary, but neither AGENT.md's capability map
  nor architecture.md mentions the audit role explicitly. Worth a
  one-line mention in AGENT.md so future readers don't see the
  spec-auditor as orphaned.
- AGENT.md says "Sub-agents are *context tools, not capability tools*"
  while `spec/architecture/06-ui-and-cockpit.md` and the
  `ui-test-harness-bootstrap` brief describe sub-agent driven test
  workflows that approach the boundary (test-runner ↔ evaluator
  split). The boundary is preserved (evaluator is read-only, no live
  app), but a casual reader may interpret these as conflicting. Both
  documents agree once the test-runner/evaluator distinction is
  loaded; recommend a forward-link from AGENT.md's capability map to
  the test-runner/evaluator split below it for self-consistency.

**Confidence: medium.** This is a wording / cross-reference issue, not
a contradiction in operational behavior. Operator may safely defer.
