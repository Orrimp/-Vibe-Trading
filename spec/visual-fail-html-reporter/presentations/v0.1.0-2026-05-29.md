# Visual-fail HTML reporter — v0.1.0 — release

## TL;DR

- A new helper auto-emits a single self-contained `target/visual-diff/visual-fail-<test>-<ts>.html` (baseline + actual + perceptual-diff PNGs inlined as base64, plus the assertion text) on every visual-snapshot test FAIL across `crates/ui/tests/`.
- Operator triage on a failed visual goes from "open three PNGs in Preview + cross-reference test source" (~5 min) to "open one HTML in Safari/Chrome" (~30 s). PASS path is byte-identical — zero new file output on green tests.
- Tester PASS at commit `d44dae5`: 8/8 gates green, 75/75 anchors PASS byte-identical, self-tests 2/2 PASS across 3 consecutive runs, `.claude/agents/tester.md` amendment in place.

## What changed

- **`crates/ui/tests/fixtures/visual_fail_html.rs`** — NEW (476 LoC: ~165 LoC helper + ~211 LoC self-test pair + ~100 LoC error type / utilities). Exports `VisualFailContext<'_>`, `VisualFailHtmlError`, `emit_visual_fail_html(ctx) -> Result<PathBuf, _>`. HTML template per architect D-VF-1 skeleton; base64 encoding via `base64::engine::general_purpose::STANDARD`; PNG dimensions via `image::ImageReader`.
- **`crates/ui/tests/fixtures/visual_diff.rs`** — wired 3 FAIL-path call sites (DimensionMismatch ~line 120, Mismatch ~line 155, `matches_rgb_buffers` Mismatch ~line 205). Each uses `eprintln!` on emit error and preserves the original `VisualDiffError::Mismatch` return verbatim (D-VF-5 contract).
- **`crates/ui/tests/fixtures/mod.rs`** — registers `pub mod visual_fail_html;`.
- **`crates/ui/tests/visual_fail_html_self_test.rs`** — NEW integration-test entry point; lets Cargo discover the `#[test]` fns inside `visual_fail_html::tests`.
- **`crates/ui/Cargo.toml`** — `base64 = "0.22"` + `chrono = { version = "0.4", default-features = false, features = ["clock"] }` added under `[dev-dependencies]` only. Zero production-dep change. Both already present in `Cargo.lock` transitively.
- **`.claude/agents/tester.md`** — new top-level section `## Visual failures — HTML artifact emission` (22 lines, D-VF-4 verbatim) inserted at line 135, between `## Tick discipline (T_FINAL ownership)` and `## Handoff`. Section count: 10 → 11.
- **`spec/trace.toml`** — `REQ-VISUAL-FAIL-HTML-REPORTER-001` row updated to `state = "dev-done"` with `crates = ["crates/ui"]` and the two self-test fn names.

## Why

Per the `ui-testability-deep-dive-2026-05-15.md § 4.1` analysis, visual-snapshot FAILs forced the operator to open three separate files in Finder/Preview (`<test>.png` diff, `<test>-actual.png`, baseline PNG) and triangulate the failure manually, then the tester wrote ~30 lines of prose into the test-final report repeating what the PNGs already showed. This feature closes the agent-contract gap with default-FAIL emission of a self-contained HTML artifact that combines all three PNGs + the assertion text in one file. Cross-cuts every future UI feature without per-call wiring — the helper is wired once at `matches_screenshot`. Per the trifecta direction this was the cheapest of three Pick A pillars (~1 dev day, LARGE per-cycle benefit, LOW maintenance). See [`spec/visual-fail-html-reporter/feature.md`](../feature.md) § Why.
