# UI contrast asserter v0.1.0 — release

## TL;DR

- **A new test (`crates/ui/tests/contrast.rs`, 959 LoC) enumerates every `(foreground, background)` color-token pair in the Lumen theme — 83 pairs total, 9 explicit opt-outs — and asserts the W3C WCAG 2.1 contrast formula (4.5:1 for body text, 7:1 for the equity display).** Closes the entire palette-refactor regression class without rendering a single pixel.
- **Ships in WARN mode at v0.1.0**: 7/7 tests PASS, with **6 design-intent sub-AA pairs logged to stderr as `WARN:` lines** (these are NOT bugs introduced today — they are pre-existing palette-debt that this asserter exists to surface). After a 2-week observation window the default flips to `gate` at v0.2.0 (target 2026-06-12), at which point those 6 pairs become CI-blocking unless upstream-tuned first.
- **Cost recap**: ~0.5 dev-day actual (matched architect estimate). Zero production code touched, zero new dependencies, zero anchor delta (`verify_anchors.sh` 75/75 PASS byte-identical pre/post). Tester `VERDICT → PASS` at commit `c0a50df`.

## What changed

- **NEW `crates/ui/tests/contrast.rs` (959 LoC, single file).** Hand-rolled WCAG 2.1 relative-luminance + contrast-ratio formula (3 pure functions, ~20 LoC); `ContrastPair { pair_id, fg, bg, class }` data struct; `ContrastClass { Body, Equity, OptOut(&'static str) }` enum; `const PAIRS: &[ContrastPair]` with 83 enumerated entries; `const OPT_OUTS: &[OptOutEntry]` with 9 reason-stringed opt-outs; `MIN_PAIRS: usize = 60` enumeration-shape floor; env-var-gated WARN-vs-gate mode dispatch (`UI_CONTRAST_MODE=warn|gate`, default `warn`); 7 `#[test]` functions (4 reference vectors + 3 invariants) + 2 `#[ignore]`d falsification probes.
- **Zero production code touched.** `git diff -- crates/ui/src/` is empty (R-NR.1 contract holds). Test reads `pub const` tokens from `crates/ui/src/theme.rs` via the public API only.
- **Zero new dependencies.** Hand-rolled formula per Q-CONT-2 (a) DURABLE ratification; no `[dev-dependencies]` add. The WCAG 2.1 math is closed (W3C-locked), so dep-vs-LoC trade-off favours the 20-LoC inline formula.
- **In-file `OPT_OUTS` table** per Q-CONT-3 (a) DURABLE ratification — test-only metadata stays out of production `theme.rs`; new opt-outs require touching ONE file and carry mandatory `reason: &'static str`.

## Why

The Lumen theme at [`crates/ui/src/theme.rs`](../../../crates/ui/src/theme.rs) defines ~30 `ModeColor` constants (FG_1/2/3/4 ladders, CANVAS, PANEL, ACCENT, UP/DOWN/WARN/INFO_500, etc.) consumed across the cockpit in `(fg, bg)` combinations. The [`ui-design-principles.md ## Accessibility minimums`](../../ui-design-principles.md#accessibility-minimums) contract requires **≥ 4.5:1 contrast** for body text (WCAG 2.1 AA) and **≥ 7:1** for the equity display (AAA). Until today that contract was enforced only by human eyeball during design review. A palette refactor — even an unrelated hex-value tweak to `FG_3.dark` — could silently drop a `(FG_3, PANEL)` pair below 4.5:1 with no test catching it; the operator would notice the legibility regression at the next cockpit launch, days or weeks after the offending PR landed. This asserter closes that gap: every existing token now inherits a per-pair WCAG check, and any new token added to the `PAIRS` table inherits the same check automatically. Per the [`pick-b-cross-cutting-safety-duo-2026-05-29.md`](../../dev-notes/pick-b-cross-cutting-safety-duo-2026-05-29.md) bundle direction, this is the cheaper of two cross-cutting safety duo pillars (~0.5 dev-day actual; the sibling `v2-1-tracing-layer-redactor` is mid-flight at ~1.5 dev-days). See [`spec/ui-contrast-asserter/feature.md`](../feature.md) § Why for the full analyst rationale.

## The 6 design-intent WARN lines — what they mean and who decides

The asserter is doing its job. Each line below is a `(fg, bg)` pair that the architect's M-T1 dry-run audit predicted would fail, and that the v0.1.0 ship deliberately surfaces during the 2-week observation window. Operator decides at v0.2.0 promotion (2026-06-12) which of the four mitigation paths to apply per pair.

| Pair | Ratio | Severity | Surface | v0.2.0 decision |
|------|-------|----------|---------|-----------------|
| `fg_on_accent_on_accent_light` | **3.52** | Genuine WCAG-AA defect | Light-mode accent-button text (white on accent-400 `#3F968D`) | Tune `ACCENT.light` to accent-500 `#2A7B73` (already passes via existing `ACCENT_HOVER.light`); OR tune `FG_ON_ACCENT.light` off pure white |
| `warn_500_on_canvas_light` | **2.96** | Genuine WCAG-AA defect | Light-mode latency / warning text (amber on warm-50 canvas) | Tune `WARN_500.light` to deeper amber e.g. `#8C6324`; OR downgrade affected widgets to `WARN_400` darker variant |
| `warn_500_on_panel_light` | **3.11** | Genuine WCAG-AA defect | Light-mode warning text on panel surface | Same as above (`WARN_500.light` is the shared root cause) |
| `up_500_on_canvas_light` | **4.46** | Marginal sub-AA | Light-mode P&L green text on canvas | Monitor during WARN window; widget surface audit decides if `CANVAS` is hit in practice or only `PANEL` |
| `down_500_on_canvas_light` | **4.33** | Marginal sub-AA | Light-mode P&L red text on canvas | Same as above (`DOWN_500.light` parallels `UP_500.light`) |
| `fg_3_on_panel_raised_dark` | **3.75** | Marginal sub-AA | Dark-mode tertiary text on dialog popovers | Tune `FG_3.dark` from `#808993` to `#9098A2` to raise contrast; OR opt-out with reason `"dialog-tertiary-label-decorative"` if widget audit shows usage is non-body |

All 6 are **observation signals, not regressions.** This PR introduces zero new sub-AA pairs — it makes the existing palette debt visible for the first time.
