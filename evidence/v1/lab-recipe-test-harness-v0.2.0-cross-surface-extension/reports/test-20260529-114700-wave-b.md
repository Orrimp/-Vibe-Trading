## 8. Falsification Probe Results (per ADR-0048 D2 / Q2=(a) durable contract)

All three probes were independently executed in this tester environment with full mutation-apply → run → restore → re-verify cycle. Production file restored to verbatim post-each probe and re-verified 3/3 PASS before proceeding to the next probe.

### P-B1 canonical — recv arm replaced with `futures::future::pending::<()>()`

**Mutation applied:** In `pub async fn run_aggregator_loop`, the recv arm:
```
recv_result = agg.rx.recv() => { ... }
```
replaced with:
```
_ = futures::future::pending::<()>() => { unreachable!() }
```

**Command:** `cargo test -p agent --test activity_audit_aggregator_select_arm_survival`

**Result:** `test result: FAILED. 0 passed; 3 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s`

All 3 tests FAIL with the expected assertion messages:
- `recv_arm_increments_after_interval_fires` — "aggregator did not exit within 500 ms after bus.close() — recv arm must process RecvError::Closed to break the loop."
- `recv_arm_survives_n_interval_boundaries` — "aggregator did not exit within 500 ms after bus.close() — recv arm must survive N interval boundaries and process RecvError::Closed."
- `recv_arm_increments_counter` — "expected >= 1 Start event — proves recv arm incremented counter (fetch_add) and interval arm drained it (counter.swap). Got 0."

**Verdict: P-B1 CANONICAL CONFIRMED** — harness genuinely catches recv-arm starvation (the Bug #64 select-arm regression class). Probe matches developer's dry-run evidence exactly.

**Source restored verbatim** before proceeding.

### P-B1 deviation verification — `biased;` with `interval.tick()` arm FIRST

Per the orchestrator brief, the original P-B1 spec described adding `biased;` with the interval arm listed first, and the dev claimed this does NOT cause observable test failure under `tokio::time::pause()`. The tester independently verified this claim.

**Mutation applied:** Added `biased;` to `tokio::select!` with the `interval.tick()` arm listed first and `recv_result = agg.rx.recv()` arm listed second (both arms present; only ordering + biased changed).

**Command:** `cargo test -p agent --test activity_audit_aggregator_select_arm_survival`

**Result:** `test result: ok. 3 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.00s`

**Finding — DEVIATION CONFIRMED CORRECT:** Under `tokio::time::pause()` + `advance()`, all pending futures are polled cooperatively when the runtime yields. The `biased;` keyword sets polling order for futures that are BOTH ready simultaneously, but under the paused-clock test model, the cooperative scheduler ensures the recv arm still gets polled when ticks arrive via `tx.send()`. The `pending` substitution (P-B1 canonical) removes the recv arm entirely — that IS observable. The `biased;` reorder does NOT remove the arm and is therefore not detectable by these tests.

The dev's deviation explanation is accurate: P-B1 canonical (`pending` substitution) is the correct falsification for this test design. The `biased;` + interval-first reorder would only be observable in a real-time multi-thread test where the interval consistently starves the recv arm under load — not under `start_paused = true`. The tester's production docstring in `run_aggregator_loop` describes P-B1 as the biased-reorder probe, which is aspirationally correct for the real-time risk it guards against, but the test design correctly uses the `pending` substitution to observe the actual starvation outcome.

**Verdict: P-B1-DEVIATION CONFIRMED** — biased reorder does NOT cause observable test failure under `tokio::time::pause()`. Dev's explanation is correct. Not INCONCLUSIVE.

**Source restored verbatim** before proceeding.
